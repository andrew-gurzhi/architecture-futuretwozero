## 2. Roadmap изменений

### Этап 1 (0–3 месяца): Подготовка архитектуры

**Цели:**
- Определение доменов
- Проектирование Data Platform

**Действия:**
- Анализ текущих данных
- Выделение доменов
- Проектирование Event Streaming

**Результат:**
- Архитектура согласована
- План миграции готов

**Команды:**
- Архитекторы
- Data Engineers

**Ресурсы:**
- Время на анализ
- Архитектурные инструменты

---

### Этап 2 (3–6 месяцев): Запуск Data Platform

**Цели:**
- Уход от DWH
- Подготовка данных для аналитики

**Действия:**
- Развёртывание Data Lake
- Настройка Kafka
- Интеграция доменов через события

**Результат:**
- Данные поступают в Data Lake
- Начало отказа от DWH

**Команды:**
- Data Platform Team
- Backend команды

**Ресурсы:**
- Облачная инфраструктура
- DevOps

---

### Этап 3 (6–9 месяцев): Self-service витрина

**Цели:**
- Запуск портала аналитики

**Действия:**
- Подключение BI к Data Lake
- Реализация Data Portal
- Настройка Data Catalog

**Результат:**
- Пользователи могут строить отчёты самостоятельно
- Ускорение аналитики

**Команды:**
- BI команда
- Data Engineers

**Ресурсы:**
- BI инструменты
- UX/UI

---

### Этап 4 (9–12 месяцев): Независимость доменов

**Цели:**
- Полная доменная изоляция

**Действия:**
- Вынос логики из DWH
- Переход на event-driven
- Интеграция новых бизнесов

**Результат:**
- Домены работают независимо
- Быстрое подключение новых сервисов

**Команды:**
- Backend команды
- Integration team

**Ресурсы:**
- Разработчики
- Kafka инфраструктура

---

### Этап 5 (параллельно): Безопасность и соответствие

**Цели:**
- Защита медицинских и финансовых данных

**Действия:**
- Разграничение доступа
- Шифрование данных
- Аудит

**Результат:**
- Соответствие требованиям регуляторов

**Команды:**
- Security team

**Ресурсы:**
- Security инструменты
